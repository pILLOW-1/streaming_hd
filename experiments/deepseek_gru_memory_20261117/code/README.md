# Method code and data interface

The method is dependency-light: Python 3.11+, PyTorch, NumPy and scikit-learn. Recorded training used Python 3.11.16, PyTorch 2.7.1+cu128, NumPy 2.2.6 and scikit-learn 1.6.1. The native-cache loader may have additional dependencies. No scheduler is required by this code.

## Dataset adapter

Supply a factory `module:function(private_config_dict)` that returns the project's **verified** dataset object. The factory and private JSON stay with the local data pipeline; this package does not claim to verify external feature bytes itself. Use the exact model/layer, original Step indices and HF split identities in `../config/protocol.json`. Preserve the published split and both independent label sequences. Do not replace Prefix labels with a cumulative OR.

| Member | Required value |
| --- | --- |
| `width` | 4096 for the reported DeepSeek experiment. |
| `identity` | Stable JSON-serializable mapping binding model/domain, split, feature and source hashes. It must distinguish incompatible assets. |
| `split(name, smoke=False)` | Ordered opaque rows for `train`, `val`, or `test`. No question group may cross splits. |
| `load(row)` | One trajectory with `.steps`, float `.step_labels` and `.prefix_labels` tensors, plus `.metadata`. |
| `trajectory.steps` | Completed Steps, each exposing `.hidden_states` with shape `[tokens,4096]` and original integer `.step_id`; optional `.offsets`. |
| `trajectory.metadata` | `trajectory_id`, `split`, nonempty `group_keys`, `source_row_sha256`, and optional independent `answer_label`, feature/span identities and eligibility fields. |

The original HF adapter already exposes this interface. The repository's Qwen pooling arrays are not drop-in inputs: this Step encoder uses native token features, not only prepooled 128-dimensional vectors. Integrating another loader requires checking row order, tensor identity, labels and span handling. Missing native assets are not generated by this method package.

## Run

From the experiment folder, after installing `requirements.txt`, make your existing adapter module importable. In these examples `my_cache_adapter:make_dataset` is a placeholder for that local adapter, not a bundled module. Use separate output roots per domain and a new output root for the compact package, because its code identity differs from the historical full release.

```bash
for seed in 42 123 456 789 2026; do
  python train.py train --dataset-factory my_cache_adapter:make_dataset \
    --data-config /external/logic_data.json --output-root /external/new_logic_runs \
    --seed "$seed" || exit "$?"
done
for seed in 42 123 456 789 2026; do
  python train.py evaluate --dataset-factory my_cache_adapter:make_dataset \
    --data-config /external/logic_data.json --output-root /external/new_logic_runs \
    --seed "$seed" || exit "$?"
done
```

Training uses only TRAIN and VAL. Evaluation refuses to start until all five fixed seed fits are complete, then evaluates each selected checkpoint on TEST. A saved pause returns exit 75; resume with the same code, data identity, runtime, paths and seed. Existing artifacts are checked before reuse. Keep weights and raw prediction exports outside Git.

For direct integration put `code/` on Python's import path, call `gru_memory.model.build_model(4096, gru_memory.config.config_for("gru_memory"))`, or call `gru_memory.api.execute(dataset, output_root, seed, phase, ...)`. Source integrity is checked against `gru_memory/PACKAGE_SHA256.json` before full training/evaluation. Changing code requires a new package identity and output root.

Original core functions are retained, with unused graph/other-dataset code and cluster orchestration removed. The compact model factory must preserve the original initialization order and architecture metadata; CPU validation compares it with the original source. These checks do not constitute a real-data GPU rerun. Streaming is a historical comparator here; its full original training source remains in the separate reproduction archive.
